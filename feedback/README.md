# 试用反馈汇总

> 目的：把 5 个团队的零散反馈，变成「该改哪条规则、该补哪段文档」的清单。

## 文件

| 文件 | 用途 |
|---|---|
| `试用反馈汇总表.csv` | 主表，Excel / WPS 直接打开。前 3 行是示例，**填之前删掉编号以「示例-」开头的行** |
| `summarize.mjs` | 汇总脚本：按分类 / 严重度 / 命中规则 / 待处理项统计 |

真实数据建议另存为 `试用反馈汇总表.local.csv`（已在 `.gitignore` 里），避免把第三方的名字和命令提交进仓库。

## 怎么收集

发给试用者的问题就五个（`docs/trial-invite.md` 里也有）：

1. 你在哪个客户端、什么系统上试的？
2. `check` 的输出里，**哪几条是你日常真的会用**的命令？（被误拦的关键信号）
3. 你的 agent 干过什么「差点出事」的事，这次**没拦住**？
4. 接入过程有几步是被卡住的？
5. 如果只能保留一条规则，你保留哪条？为什么？

## 怎么填

| 列 | 填法 |
|---|---|
| 分类 | `误拦` / `漏拦` / `接入卡点` / `体验` / `其他` |
| 严重度 | `P0 阻塞`（装不上 / 用不了）、`P1 影响使用`（正常操作被拒）、`P2 建议` |
| 命中规则 | 从 `check` 或 `audit list` 输出里抄，没有就写「（未命中规则）」 |
| 参数摘要 | 只记**能复现问题的关键参数**，别把对方完整命令或路径贴进来 |
| 处理结论 | `加基线放行` / `加 deny 规则` / `放宽规则` / `文档补充` / `不修（理由写备注）` |

## 怎么用

```powershell
# 填完之后跑一次
node feedback/summarize.mjs feedback/试用反馈汇总表.local.csv
```

输出会直接告诉你三件事：

- **哪条规则被误伤最多** → 优先改它（`误拦` + 同一 `命中规则` ≥ 2 次）
- **哪些还没处理** → 逐条给结论
- **结论分布** → 有多少变成了规则改动、多少只是文档问题

## 分类的判断标准

**误拦**：正常开发操作被拒。处理方向只有一个——放宽或加基线放行，并且**必须补一条回归用例**。

**漏拦**：该拒绝的没拒绝。要先分清是「规则没写」还是「规则写错了」：
- 规则没写 → 加规则（进对应策略包）
- 规则写了没命中 → 是 bug，先复现再改

**接入卡点**：装不上、连不上、配置写错。90% 是文档问题，不是代码问题——这类反馈最容易被忽略，但它决定了别人会不会给第二次机会。

## 两条红线

1. **不要因为一条反馈就改规则**。同一条规则被误伤两次以上，或者漏拦的是「人类会立刻后悔」级别的操作，才值得动。
2. **改完规则必须跑 `npm.cmd run check:all`**。规则是产品的核心，改规则等于改行为，没有测试兜着就是裸奔。
