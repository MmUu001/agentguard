# 掘金沸点文案

> 沸点 = 短内容（类似微博），不是文章。目标不是推销，是**让人知道以后关注你能看到什么**。
> 1–3 句话 + 一张图，配话题标签。

---

## 推荐版（立系列，最适合"长期输出"定位）

```
打算在掘金做个系列：AI agent 的「事故档案」。

每期一个真实场景——agent 执行 rm -rf 时路径少写一层、把 .env 内容贴进 issue、
逻辑 bug 循环调用付费 API 烧掉几百刀。每期都给能复现的最小案例，加一条真能落地的防线。

第一期已经发了：在 MCP 层给工具调用加一道本地闸，一份 YAML 决定哪些事不许做。
不接 agent 也能 30 秒自测：npx -y @leeruu/agentguard@beta demo

顺带征集素材：你的 agent 干过什么「差点出事」的事？评论区说，我大概率写成下一期。
```

**为什么这么写**：
- 「做系列」= 给出关注理由，比"我做了个工具"强
- 三条具体场景 = 让人立刻对号入座
- 最后一句 = 把评论区变成选题来源，**反馈和素材一起来**


## 发的时候注意

| 项 | 建议 |
|---|---|
| **时机** | **文章发出去 10 分钟后再发沸点**，带文章链接。先有正文，沸点才不空洞 |
| **配图** | 用封面图或终端截图。1200×630 在信息流里会被裁，**建议裁一张 1:1 或 4:5** |
| **话题** | 有对应的就带，比如 `#AI#` `#程序员#` `#MCP#`（以平台现有话题为准，别硬造） |
| **链接** | 全文只放一次，放正文里，不要放在开头 |
| **不要** | 不要写「求关注」「新人报到」「开号第一篇」——这三个词会让内容显得没有分量 |
| **不要** | 不要在沸点里贴微信群/公众号，掘金对导流敏感 |

## 后续沸点选题库（一次想好，省得每天憋）

有真实进展就发，不要空发。每条都能在 5 分钟内写完：

| 类型 | 例子 |
|---|---|
| **反馈回应** | 「有同学说 X 命令被误拦了，我看了下是基线没覆盖 MCP server 的工具名，0.1.1 补上了」 |
| **单个规则拆解** | 「为什么 `git push --force-with-lease` 必须放行——它是强制推送的安全版本，写错一个字符就误伤所有人」 |
| **事故复盘** | 「今天又被问到：`.env` 被 agent 读出来贴进 issue。这类问题的防线不在 agent，在工具调用那一层」 |
| **数据/反差** | 「27 条规则里，真正会误伤日常开发的只有 2 条，剩下 25 条几乎不可能误报」 |
| **技术选择** | 「为什么不用 LLM 判断命令危不危险：要可复现、可解释、可审计，LLM 三样都做不到」 |
| **踩坑记录** | 「npm 的相似性策略把 agentguard 拦了（和 agent-guard 太像），只能改 scoped 名」 |

**节奏**：一周 2–3 条，全是有信息量的；不要为了活跃度发「今天也在写代码」这种。
