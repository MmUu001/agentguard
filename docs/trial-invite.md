# 试用邀请话术（可直接复制）

> 目标：拿到 5 个真实团队的 10 分钟试用 + 1 条有效反馈。
> 原则：短、具体、给对方一个明确的退出理由。

---

## A. 私聊短版（微信 / 飞书 / Slack，控制在 3 句）

> 我在做一个 MCP 网关：夹在你的 agent 和 MCP server 之间，用一份 YAML 拦住 `rm -rf /`、读 `.env`、`git push --force` 这类操作。改 MCP 配置一行就生效，不改 agent、不换环境。
> 能花 10 分钟试一下吗？装完有个 `check` 命令，**先不接入就能看到你自己的 agent 会被拦什么**。
> 不合适直接说不用，不影响。

**为什么这么写**：第三句是退出口。没有退出理由的邀请，对方只能已读不回。

---

## B. 邮件版

**主题**：10 分钟试一下 MCP 的本地权限闸？

> Hi `<名字>`，
>
> 我在做一个给 AI coding agent 用的本地权限网关，想请你试 10 分钟。
>
> **它解决什么**：agent 执行 `rm -rf ./build` 时路径拼错成 `./`、把 `.env` 内容贴进 issue、为了"清理历史"执行 `git push --force` —— 这些事没有"手滑一下"的缓冲。现在的防护要么是人肉点确认（第三次之后就开始无脑允许），要么是换沙箱环境（太重）。
>
> **它怎么做**：在 MCP 配置里把 server 命令包一层，`--` 前面加个 `--policy`。agent 完全不知道中间多了个进程。策略是一份 YAML，比如：
>
> ```yaml
> - id: block-rm-rf-root
>   match:
>     tool: [bash, shell, run_command]
>     args.command: { regex: 'rm\s+(-[a-zA-Z]+\s+)*-(rf|fr)\s+/' }
>   decision: deny
> ```
>
> **你会先看到什么**：装完有个 `check` 命令，打印一张预演表——`rm -rf /` 被拒、`rm -rf ./build` 放行、`git push --force-with-lease` 放行。**这一步还不接入任何东西**，只是让你看看会不会误伤。
>
> **装法**（Node ≥ 20，约 3 分钟）：
> ```bash
> npx --yes <tgz 绝对路径> init --yes
> npx --yes <tgz 绝对路径> check
> ```
> 然后把 init 打印的那段 JSON 粘进你的 MCP 配置。
>
> **想请你回三个问题**：
> 1. `check` 里有你日常真的会用的命令被误拦吗？
> 2. 你的 agent 干过什么"差点出事"的事，是这里没拦住的？
> 3. 接入卡在哪一步？
>
> **隐私**：不联网、不上报、不需要账号。策略和审计都在你本机 `~/.agentguard/`，不想留审计设 `AGENTGUARD_AUDIT=off`。
>
> 需要的话我把一页纸说明发你。不合适直接说不用，真的不影响。
>
> `<你的名字>`

## C. 社群 / 群发版（一条，不刷屏）

> 分享一个自己写的东西：**MCP 工具调用的本地防火墙**。
>
> 不改 agent、不换环境，在 MCP 配置里把 server 命令包一层，用一份 YAML 决定哪些调用不许做。默认拦 `rm -rf /`、读 `.env`、`git push --force`、写 `/etc`，放行日常开发。
>
> 装完不接入也能跑 `check`，先看自己的 agent 会被拦什么：
> ```
>   deny   rm -rf /                     ← core-rm-rf-root
>   allow  rm -rf ./build               ← base-allow-command
>   allow  git push --force-with-lease  ← base-allow-command
> ```
>
> 有误伤的具体命令欢迎直接骂，规则改起来很快。

**为什么克制**：群发最容易变成噪声。给一条能自己验证的命令，比贴十张图有用。

## E. 反馈问题清单（直接粘给对方）

1. 你在哪个客户端、什么系统上试的？（Windows 用户我特别想知道）
2. `check` 的输出里，哪几条是**你日常真的会用**的命令？（被误拦的关键信号）
3. 你的 agent 干过什么"差点出事"的事，这次**没拦住**？
4. 接入过程有几步是被卡住的？（装包 / 改配置 / 重启 / 报错）
5. 如果只能保留一条规则，你保留哪条？为什么？

## F. 红线

| 不做 | 原因 |
|---|---|
| 不承诺"100% 安全""彻底防住" | 它只看请求方向，响应侧没做。夸大会在第一次翻车时把信任清零 |
| 不催第三次 | 试用是帮忙，不是 KPI |
| 不要对方的项目代码 | 只要 `check` 输出和 stderr，或者脱敏后的那条命令 |
| 不说"竞品很差不安全" | 只讲位置不同（hook / 沙箱 / LLM 网关各管一段），不提别人产品名贬低 |
| 不把未实现的功能写进材料 | 响应侧检查、交互式审批、域名白名单都是缺口，材料里明确写"没做" |
